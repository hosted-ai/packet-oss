# Token Usage Dashboard

## Overview

The Token Usage Dashboard provides analytics on the token consumption of the vLLM inference servers running on your own GPU instances. Track prompt and generation tokens over time, see which instances consume the most tokens, and export data for billing reconciliation or capacity planning.

### Key Features

- **Usage Tracking**: Monitor prompt, generation, and total token counts
- **Time-Based Analysis**: Group usage by day, week, or month
- **Instance Breakdown**: See which GPU instances consume the most tokens
- **Cost Estimation**: Approximate costs based on token usage
- **Export Capabilities**: Download reports as CSV (JSON via the API)

---

## 🚀 Quick Start

### Accessing Token Usage

1. Navigate to your Packet.ai Dashboard
2. Click **"Metrics"** in the sidebar navigation
3. Click the **"Token Usage"** button at the top of the Metrics page
4. The Token Usage Dashboard opens showing your last 30 days of usage

### Understanding Token Metrics

| Metric | Description |
|--------|-------------|
| **Prompt Tokens** | Tokens in the inputs sent to your models |
| **Generation Tokens** | Tokens generated by your models |
| **Total Tokens** | Prompt + Generation combined |
| **Estimated Cost** | Approximate cost based on total token volume |

## 💰 Cost Estimation

Packet.ai charges by GPU-hour, not per token. The **Estimated Cost** figures shown in the dashboard are indicative only: they apply a flat rate of **$0.04 per 1,000 tokens** to your recorded token volume. Use them to gauge relative usage between instances and periods, and to compare against pay-per-token API pricing — your actual bill is determined by your GPU instance pricing, not these estimates.

## 🔌 API Reference

All endpoints require your Packet.ai session token in the `Authorization` header (the same Bearer token the dashboard uses).

### Get Token Usage

```bash
GET /api/token-usage?period=day&from=2026-06-30T00:00:00Z&to=2026-07-30T00:00:00Z
Authorization: Bearer YOUR_SESSION_TOKEN
```

**Query parameters**:

| Parameter | Values | Default |
|-----------|--------|---------|
| `period` | `day`, `week`, `month` | `day` |
| `from` | ISO date string | 30 days ago |
| `to` | ISO date string | now |
| `format` | `json`, `csv` | `json` |

### Collect a Metrics Sample

Trigger an on-demand collection from an instance's vLLM server:

```bash
POST /api/vllm-metrics
Authorization: Bearer YOUR_SESSION_TOKEN
Content-Type: application/json

{"subscriptionId": "SUBSCRIPTION_ID"}
```

This reads the vLLM `/metrics` endpoint on the instance and stores a sample (cumulative counters plus deltas since the previous sample). The instance's vLLM API service (port 8000) must be exposed first — see [Service Exposure](./service-exposure.md).

## 🧮 Token Counting

### How Tokens Are Counted

Token counts come from the vLLM server running on your instance. vLLM tokenizes requests with the deployed model's own tokenizer and publishes cumulative counters (`vllm:prompt_tokens_total` and `vllm:generation_tokens_total`) on its Prometheus `/metrics` endpoint, which Packet.ai samples and aggregates.

Rough rules of thumb for estimating token counts:

| Content | Approximate Tokens |
|---------|-------------------|
| 1 word | ~1.3 tokens |
| 1 sentence | ~15-20 tokens |
| 1 paragraph | ~100-150 tokens |
| 1 page (500 words) | ~650 tokens |
| Code (1 function) | ~50-200 tokens |

### Estimating Before Requests

Exact counts depend on the model's tokenizer, but you can approximate ahead of time:

```python
# Python example using tiktoken (approximation only —
# your deployed model's tokenizer may differ)
import tiktoken

encoding = tiktoken.get_encoding("cl100k_base")
tokens = len(encoding.encode("Your prompt here"))
```

## 📚 Best Practices

### Reducing Token Usage

1. **Concise Prompts**: Remove unnecessary words
2. **System Prompts**: Reuse across conversations
3. **Caching**: Cache common responses
4. **Summarization**: Compress conversation history
5. **Early Stopping**: Set appropriate max_tokens

### Optimizing Costs

```
Token Optimization Checklist:
☑ Set reasonable max_tokens limits
☑ Use stop sequences for structured output
☑ Implement response caching
☑ Compress conversation history
☑ Monitor for prompt injection (large inputs)
☑ Use smaller models for simple tasks
```
